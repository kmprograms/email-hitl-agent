# Human-in-the-Loop Email Agent

**Język / Language:** [Polski](README.md) | **English**

---

A LangGraph agent demo for writing B2B emails with mandatory human approval before sending. Showcases practical use of LangGraph's `interrupt()` mechanism — the agent pauses mid-execution, waits for the user's decision (approve / revise with feedback), and resumes work from exactly the same place.

CLI in the terminal, colorful interface via `rich`, OpenAI as the LLM backend.

> **Note:** The emails generated by this agent are in Polish (the system prompt and templates are Polish-language). The CLI is also Polish. This README is the English documentation; the application itself is a Polish-language tool.

## Features

- Generates professional Polish-language emails from 3 inputs: recipient, company, email purpose.
- **Human-in-the-loop**: after generating a draft, the agent waits for a decision — `Y` (send) or `N` (revise with feedback).
- Revision loop: the model receives the feedback and applies corrections instead of rewriting from scratch. A revision limit protects against infinite loops (default 3, then auto-approve).
- Email "sending" = writing an `.eml` file to the `sent/` directory (easy to swap for SMTP / SendGrid without touching the rest of the graph).
- Clean terminal UI: banner, panels, spinner during LLM calls, colorful error messages.

## Architecture

A LangGraph graph with three nodes and an `interrupt()` mechanism that pauses execution:

```
START → draft_email → human_review → send_email → END
              ↑              │
              └──────────────┘
              Command(goto="draft_email") on revise
```

### Nodes

| Node           | Role                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| `draft_email`  | Calls the LLM (ChatOpenAI). On revision, appends a section with human feedback.                        |
| `human_review` | Calls `interrupt()` — the graph pauses, state goes to the checkpointer, execution returns to `main.py`.|
| `send_email`   | Writes the final email to `sent/<timestamp>_<slug>.eml`.                                               |

### Graph state (`EmailAgentState`)

A `TypedDict` passed between nodes and serialized by the checkpointer after each step. Holds the user input, current draft, human decision, feedback, revision counter, and status.

### Checkpointer

`InMemorySaver` — state lives in process memory. State is lost when the program exits. In production, simply swap to `PostgresSaver` / `RedisSaver` so state survives restarts and the graph can be resumed from another process.

### The `interrupt()` mechanism

`human_review` calls `interrupt(payload)`:

1. LangGraph writes the current state to the checkpointer.
2. Raises `GraphInterrupt` — `graph.invoke()` in `main.py` returns normally.
3. The loop in `main.py` reads the state, shows the draft, asks the user for a decision.
4. Resume: `graph.invoke(Command(resume={...}), config)` — the `Command.resume` payload becomes the return value of `interrupt()`, and the graph continues from the same spot.

Without `interrupt()`, we would have to manually track where the agent stopped and what it had already done.

## Installation

```bash
git clone <repo-url> email-agent
cd email-agent
uv sync
```

`uv sync` creates `.venv/` and installs all dependencies from `uv.lock` (deterministic versions).

## Configuration

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=sk-...
```

### All environment variables

| Variable             | Required | Default         | Description                                          |
| -------------------- | -------- | --------------- | ---------------------------------------------------- |
| `OPENAI_API_KEY`     | yes      | —               | OpenAI API key.                                      |
| `OPENAI_MODEL_NAME`  | no       | `gpt-4.1-mini`  | ChatOpenAI model name.                               |
| `MODEL_TEMPERATURE`  | no       | `0.3`           | Model temperature (0.0–2.0).                         |
| `MAX_REVISIONS`      | no       | `3`             | Revision limit before auto-approve.                  |
| `SENT_DIR`           | no       | `sent`          | Directory where "sent" emails are written.           |

The configuration is validated by `pydantic-settings` at startup — a missing API key throws a clear error instead of crashing silently during the first LLM call.

## Running the app

```bash
uv run python main.py
```

The CLI will ask in sequence for:

1. Recipient's full name.
2. Recipient's company.
3. Email purpose (e.g. *"follow-up after yesterday's meeting about API integration"*).

It then displays the generated draft and asks for a decision:

- **`Y`** — send (email goes to `sent/`).
- **`N`** — reject and provide feedback. The agent generates a revised version incorporating your comments.

Exit: `Ctrl+C` or `Ctrl+D` at any time.

> **Note:** All prompts and the email itself are in Polish.

## Project structure

```
email-agent/
├── main.py              # Entry point — CLI loop driving the graph
├── src/
│   ├── config.py        # Settings (pydantic-settings) — loads .env
│   ├── model.py         # ChatOpenAI factory
│   ├── state.py         # EmailAgentState (TypedDict) — graph state
│   ├── prompts.py       # System and user prompts (PL)
│   ├── nodes.py         # 3 graph nodes: draft_email, human_review, send_email
│   ├── graph.py         # Graph wiring + checkpointer
│   └── ui.py            # CLI layer (rich) — banner, prompts, panels
├── sent/                # "Sent" emails (.eml) — gitignored
├── pyproject.toml       # Dependencies + mypy config
├── uv.lock              # uv lockfile
├── .python-version      # 3.13
└── .env                 # Secrets — gitignored, must be created
```

### Separation of concerns

- **`main.py`** knows only the public API: `build_email_agent()`, `graph.invoke()`, `Command`. It knows nothing about prompts or the LLM.
- **`src/nodes.py`** knows the LLM, prompts, file IO — all the domain logic.
- **`src/ui.py`** knows only `rich` and user input. Can be swapped for FastAPI/Streamlit without touching the rest.
- **`src/config.py`** — single source of truth for configuration, validated at startup.

## What's next (production)

This project is a demo, but the architecture is production-ready. Migrating to production requires changing three things:

1. **Checkpointer**: `InMemorySaver` → `PostgresSaver` / `RedisSaver`. State survives restarts and the graph can be resumed from another process (e.g. a webhook hours later).
2. **Sending layer**: in `send_email`, replace `Path.write_text()` with an SMTP / SendGrid / Mailgun call. The rest of the graph stays untouched.
3. **UI layer**: CLI → FastAPI/WebSocket. The nodes are synchronous, so under FastAPI they go into a `ThreadPoolExecutor` to avoid blocking the event loop. Instead of asking in the terminal, `human_review` waits for an HTTP request carrying the user's decision (graph UUID = `thread_id`).

None of the above requires changes to `state.py`, `prompts.py`, or `graph.py`.
